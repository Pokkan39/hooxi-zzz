## 6. 配色与协调问题（诊断，不下令施工）

### 6.1 当前问题现象（对用户观感的技术翻译）

1. **双主题打架**：旧 `styles`/`multi-page` 与 `theme-zzz` 叠压，局部仍像「深色皮肤套在另一套组件上」。  
2. **背景偏脏偏死**：近黑 + 浊绿灰径向，易显得闷，而不是录像店夜色或干净 HUD。  
3. **黄色用得碎**：点缀同时出现在顶栏、豆、边、按钮、图标块，没有「主强调 / 次强调 / 静默」层级。  
4. **卡片同质化**：金刚区、优先入口、剧情卡、代理人卡都是斜切+硬阴影，节奏重复。  
5. **信息层级弱**：eyebrow / 标题 / 说明 / meta 字号与灰度阶不稳，显得「吵」或「糊」。  
6. **动效先于系统**：在未统一的组件上加强 hover/tilt，会放大廉价感。

### 6.2 重构时应遵守的产品向配色原则（来自既有文档气质，不是新发明）

- 深色为主，但**表面要有 3–4 阶**（舞台底 / 面板 / 抬起 / 输入槽），避免一块死黑。  
- 主强调色克制；大按钮与关键状态才用高饱和。  
- 正文浅色足够亮；次要信息降一阶，不靠更脏的灰绿。  
- 游戏黄可以是品牌点缀，**不是整站底色滤镜**。  
- 档案层中低特效；电影感留给扉页/PLAY。

### 6.3 建议启用的 skill 路径（你点名后执行）

| 阶段 | Skill / 依据 | 产出 |
|------|----------------|------|
| 1 | 本文件拍板 | 范围 S1/S2/S3 + 视觉浓度 |
| 2 | `HOOXI-FUNCTION-VISUAL-REVIEW` + 定位书 | 不跑偏产品 |
| 3 | **Hallmark**（反 AI 味、系统化页面） | 色板、字体、首页/关键页组件规则 |
| 4 | **software-ui-ux-design** / 可读性 | 对比度、焦点、间距、状态 |
| 5 | 必要时 `grill-me` / 方案确认 | 避免再做错一代覆盖层 |
| 6 | 授权后的正式站实现 | 少文件、真 token、少叠 patch |

## 7. 推荐重构方向（仍待你批准，不写入施工）
