## 0. 一页纸摘要

### 0.1 网站是什么

**【建议】** HOOXI = Hooxi 个人品牌下的《绝区零》**剧情视频档案** + **角色关系导航**。  
用户主要在站内**找到片、看懂顺序与关联、少剧透**，再回视频平台观看。  
**HOOXI PLAY 录像店** = 可选的沉浸式入口与发现层，**不是**打开内容的唯一门槛。

### 0.2 网站不是什么

**【不做】**

- 官方绳网 / 综合大 wiki  
- 全角色数值与配装攻略站  
- 模型下载站 / 纯 WebGL 技术展  
- Active Theory 或南孚品牌复刻  
- 必须先过 3D / AI 才能查资料的门禁站  
- 开放社区、评论、投稿论坛  

### 0.3 默认 30 秒路径（【待决】可改主次）

```text
打开根地址
→ 3 秒内看懂：这是 Hooxi 的剧情录像档案
→ 一点「浏览档案」进入目录/搜索     【建议：主路径】
→ 或一点「进入录像店」走沉浸发现   【建议：副路径，可跳过】
→ 无论哪条，最终落到同一条正式档案 URL
```

### 0.4 功能优先级一览

| 级 | 功能组 | 一句话 |
|----|--------|--------|
| P0 | 主线剧情 | 按版本补课、剧透锁、上下集 |

**【建议】** 全站一种基因：**凌晨还在营业的录像店**（档案编号、标签纸、VHS/CRT 意象、店内暖 / 店外冷、大字留白）。  
**工具页先可读，品牌页先有空气感；同一屏不要又当百科又当 TVC。**

## 1. 产品定义与用户

### 1.1 要解决的问题

视频平台能播，但用户很难：

1. 按版本 / 章节**补剧情**  
2. 从**角色或阵营**找到相关视频  
3. 看懂片与片的**前后与关联**  
4. **回看**活动、幕后、对谈  
5. 在**不被剧透**的情况下判断片子讲什么  

### 1.2 用户优先级【待决】

| 优先级 | 用户 | 来站目的 | 设计必须保证 |
|--------|------|----------|----------------|
| 第一【建议】 | 补剧情 / 找片观众 | 顺序、关联、播放入口 | 不进店也能完成 |
| 第二 | 追角色 / 世界观 | 人 → 阵营 → 片 | 3 屏内说清身份与相关影像 |
| 第三 | Hooxi 观众 | 作品与幕后气质 | 品牌可感，但不挡查档 |
| 不主防 | 纯舔屏路人 | 特效 | 不把 P0 让给特效 |

### 1.3 双层结构（功能关系）

```text
┌─────────────────────────────────────┐
│  壳层：品牌落地 + HOOXI PLAY        │
│  气氛 · 发现 · 邦布问路             │
│  输出：跳进正式档案 URL             │
└─────────────────┬───────────────────┘
                  │ 深链（同一内容模型）
                  ▼
┌─────────────────────────────────────┐
│  核层：正式剧情档案                 │
│  唯一内容真相 · 搜索 · 分享 · 编辑  │
└─────────────────────────────────────┘
```

**【建议】铁律：正式 URL = 唯一内容真相。** PLAY 里「抽到的带」必须对应真实档案 id，不建第二套隐式内容库。

## 3. 视觉设计（审核重点）

### 3.1 设计目标（感受）

用户应感到：

1. **凌晨的新艾利都里，还有一家亮着的录像店**——有故事，但不恐怖、不劣质赛博堆料。  
2. **这是 Hooxi 的店与片单**，不是米哈游官方、也不是绳网换皮。  
3. **想查时很清楚，想逛时有空间**；查的时候不被粒子和辉光骚扰。  
4. 文字**克制、留白够**；档案编号和标签带来“可归档”的秩序感。  
5. 3D / 电影感只建立情绪，**内容卡片始终可点、可读、可返回**。

### 3.2 视觉基因（全站统一）

| 基因 | 用法 | 注意 |
|------|------|------|
| 档案编号 / 标签纸 | 条目、章节、角标 | 真顺序信息，不只装饰 |
| VHS / 磁带 / CRT 意象 | PLAY、少量列表装饰 | 避免整页扫描线闪瞎 |
| 店内暖 / 店外冷 | Home、PLAY、扉页 | 档案正文降低环境噪点 |
| 大标题 + 留白 | 品牌屏、章节首 | 不与信息密集区抢 |
| 克制 HUD | 主线控制台、列表 | 服务筛选，不伪造游戏任务 |

**【不做】视觉**

- 全屏不停闪的故障艺术  
- 彩虹霓虹堆满  
- AT 标志 / 案例 / 原字体文件 / 原站壳  
- 南孚品牌物料与产品片  
- 正文背后一直开着的重 3D 场景  

### 3.3 三层「用光」（同一基因，不同浓度）

| 用光 | 浓度 | 用在哪 | 用户任务 |
|------|------|--------|----------|
| **品牌光** | 中高 | Home 落地、PLAY | 认出店、愿不愿意进 |
| **工具光** | 中（清晰第一） | 搜索、主线、列表、编辑器 | 快速完成任务 |
| **电影光** | 局部高峰 | 版本序章、进店过程、章节扉页 | 情绪记忆 |

**【建议】规则：** 工具页禁止电影光压过正文字号与对比度；品牌页禁止信息密度爬到 wiki 级。

| 首屏 | 版本轨 + 筛选状态可见 |
| 卡片 | 封面比例自适应；编号/版本/类型标签清晰 |
| 剧透 | 遮罩或折叠，开启前布局不乱跳 |
| 特效 | 低；Hover 轻微抬升即可 |
| 忌 | 长卷动电影抢在列表前；正文底 3D |

#### C. 角色目录 / 阵营

| 项 | 【建议】 |
|----|----------|
| 气质 | 选人墙 + 档案库；可保留轻微 2.5D |
| 阵营色 | 识别用，不刺眼 |
| 立绘 | 有图用图，无图字母/剪影占位，**不空洞报错** |
| 动效 | 桌面悬停层次可有；触摸设备避免“必须悬停才知可点” |
| 减动效 | 停位移，保留清晰焦点态 |

#### D. 角色详情

| 项 | 【建议】 |
|----|----------|
| 布局 | 身份头区 + **相关影像**优先；故事/来源模块化栈 |
| 舞台 | 立绘可轻微视差；移动端改纵向，不挡名与按钮 |
| 游戏 UI 感 | 可有，但**读写对比度与字号按档案站**，不按战斗 HUD |
| 养成块 | 视觉上降权（次级 tab / 折叠 / 更靠下） |
| 忌 | 首屏大表数字；首屏无任何「去看片」路径 |

#### E. 活动 / 幕后

| 项 | 【建议】 |
|----|----------|
| 活动 | 时间秩序优先；卡片比沉浸舞台重要 |
| 幕后 | 略增品牌暖感与制作气质；空状态要有设计（文案+插画/符号） |
| 忌 | 无内容时用粒子特效填空 |

#### F. PLAY 录像店

| 项 | 【建议】 |
|----|----------|
| 空间 | 门、前台、左右柜、CRT 关系一眼可懂 |
| 色彩 | 室外冷、室内暖；灯光打在可交互物上 |
| UI | 热点清楚；**永久可见的「档案」逃逸口** |
| 媒体 | 预渲染 / 短序列 / 真 3D 均可，但要可降级 |
| 卡片与 3D | 可混用；点击热区以 DOM 可达为准 |
| 忌 | 中央巨遮挡；劝退式长动画；无跳过 |

#### G. 编辑器

| 项 | 【建议】 |
|----|----------|
| 气质 | 工具优先，可沿用档案 HUD 色，但密度服务编辑效率 |
| 预览 | 真页面预览比自拍一张表重要 |
| 忌 | 为“好看”减少字段说明与错误提示 |

## 4. 关键用户旅程（功能×视觉合在一起看）

### 旅程 1：补 2.x 主线（P0）

1. Home → **浏览档案**（工具光）  
2. 主线 → 点版本轨 2.x（终端感）  
3. 打开第一条 → 读无剧透摘要 → 外链观看  
4. 下一条一路点到结尾  

**失败样子：** 必须先看进店动画；摘要默认剧透；没有上下集。

### 旅程 2：从角色找片（P0–P1）

1. 搜索「安比」或目录筛选  
2. 角色页首屏看到**相关影像**  
3. 进一条主线/活动档案 → 播放  

**失败样子：** 首屏只有养成；站内没有任何片链。

### 旅程 3：为气氛进店再查（P2）

1. Home → 进入录像店（品牌光）  
2. 随便看看抽一盘 → CRT 摘要  
3. 打开正式档案（切换工具光）  
4. 随时「跳过/去档案」  

**失败样子：** 进店失败白屏；抽到的带是假数据；找不到逃逸按钮。

### 旅程 4：看幕后（P1）

1. 导后面面 → 幕后列表  
2. 有片读书，无片见空状态设计  

**失败样子：** 空白无说明，或假内容凑版。
