## 0. 先看结论

#### 0.1 一句话定位

**HOOXI 是 Hooxi 个人品牌下的《绝区零》剧情视频档案与角色关系导航站；HOOXI PLAY 录像店是用户主动进入的可选沉浸式入口，正式内容由稳定、可搜索、可分享的普通档案页面承载。**

#### 0.2 网站最终要解决的问题

用户在视频平台上能观看视频，但很难完成以下任务：

- 按版本和章节补剧情。
- 从某个角色或阵营找到相关视频。
- 理解视频之间的前后顺序和关联关系。
- 回看已经结束的活动内容。
- 找到幕后、对谈和制作内容。
- 在不被提前剧透的情况下判断一条视频讲什么。

HOOXI 的核心任务，是把 Hooxi 的视频内容整理成一个可以浏览、检索、关联和长期维护的剧情档案系统。

#### 0.3 最终产品结构

网站由两层组成：

```text
第一层：HOOXI PLAY 沉浸式录像店
├─ 负责品牌氛围
├─ 负责“随便看看”
├─ 负责“问问邦布”
├─ 负责游戏式内容发现
└─ 可以跳过，不是内容访问门槛

第二层：正式剧情档案
├─ 主线剧情
├─ 角色与阵营
├─ 往期活动
├─ 幕后与对谈
├─ 搜索与关联导航
└─ 稳定 URL、来源、剧透控制和视频入口
```

#### 0.4 根地址默认行为

根地址不自动下载完整 3D 场景，也不强迫用户先看动画。

首屏默认显示轻量 DOM 品牌落地页，并同时提供：

- **进入录像店**：用户主动启动 HOOXI PLAY 和实时 3D。
- **直接浏览档案**：立即进入普通内容导航。

这样既保留品牌效果，也避免 WebGL、模型、网络或设备性能成为访问障碍。

#### 0.5 网站不是什么

HOOXI 正式版不是：

- HoYoverse 或米哈游官方网站。
- 完整《绝区零》综合 Wiki。
- 全角色深度数值攻略站。
- 游戏模型下载站。
- 只有 3D 没有内容的技术展示站。
- Active Theory 品牌或官网复刻。
- 开放投稿社区、论坛或社交平台。
- 必须使用 AI 才能找到内容的网站。

## 1. 网站最终想要呈现的效果

### 1.1 整体感受

用户进入后，应感受到：

- 像在凌晨的新艾利都街头发现一家仍在营业的录像店。
- 画面有游戏感，但不是直接复制游戏官方 UI。
- 店内是暖色灯光，店外偏冷，形成明显空间对比。
- VHS、CRT、标签纸、档案编号和录像柜是主要视觉语言。
- 文字排版克制、留白充足，不堆满霓虹、扫描线和故障滤镜。
- 3D 只是建立空间感，内容卡片仍然清晰、可点击、可阅读。
- 用户可以探索，也可以快速离开沉浸层直接查资料。

### 1.2 视觉参考边界

Active Theory 参考以下内容：

- 暗场全屏舞台。
- 大字号标题和极简 HUD。
- 低 FOV、较强空间纵深和大留白。
- CSS 卡片的错位、抬升、指针倾斜和媒体显影。
- 克制的虹彩玻璃、边缘高光和局部后处理。
- 列表进入详情时的聚焦感和背景退后感。

不复制以下内容：

- Active Theory 名称、标志和品牌文案。
- 原站模型、项目案例、图片和视频。
- 原站字体文件。
- 原站压缩运行时和 Shader 源码。
- 原站特有的品牌场景和项目详情内容。

### 1.3 HOOXI PLAY 视觉分镜

#### 状态 A：轻量品牌落地页

画面：

- 深色背景或静态店外海报。
- HOOXI 品牌、网站定位和一句简短说明。
- 两个明确按钮：“进入录像店”“直接浏览档案”。
- 不自动播放声音。
- 不自动加载完整 GLB。

目标：首屏快速、明确、可访问。

#### 状态 B：店外

画面：

- 夜间街道和录像店正门。
- 室内暖光从门窗透出。
- 门面是画面主体，不再出现覆盖画面的蓝色 UI 实心框。
- 鼠标或触摸只产生轻微视差和门把手反馈。

交互：

- 点击门、按 Enter 或点击“进入”打开门。
- 始终有“跳过动画”和“直接浏览档案”。

#### 状态 C：开门与进入

画面：

- 门叶打开。
- 镜头缓慢进入。
- 可以使用真实 3D、预渲染视频或关键帧混合。
- 平面入场帧必须在接近店内前淡出，不能与实时模型重叠形成门框或遮挡。

交互：

- 原生滚动或明确按钮推进。
- 快速滚动直接落到目标状态，不积累动画队列。
- 可反向滚动恢复前一阶段。

#### 状态 D：店内总览

画面：

- 用户能一眼看清门、前台、左右柜、CRT 和主要灯光关系。
- 中央不能存在遮挡视线的大型蓝黑矩形、近景墙面或错误透明平面。
- 左右路线都在画面中可理解。
- 镜头不贴近货架、横梁或柜体。
- 灯光重点落在前台、左右路线和可交互物件。

交互：

- 左侧路线：“随便看看”。
- 右侧路线：“问问邦布”。
- 直接浏览档案入口仍可见。

#### 状态 E：左柜——随便看看

画面：

- 真实或原创录像柜。
- CSS 卡片与 3D VHS 物件共同工作。
- 内容以主线、角色、活动、幕后分类。
- 卡片具有纵深、悬停抬升、图片显影和清晰焦点状态。

交互：

- 悬停或键盘聚焦显示摘要。
- 点击抽取一盘录像带。
- 录像带移动到展示锚点。
- 用户可归还原位。

#### 状态 F：CRT 看片台

画面：

- CRT 或看片台成为视觉焦点。
- 展示封面、标题、版本、类型、无剧透摘要和播放入口。
- 背景场景降亮，但不能完全被黑色遮罩盖住。

交互：

- 打开正式档案。
- 返回货架。
- 归还录像带。
- Escape 返回上一层。

#### 状态 G：右侧——问问邦布

画面：

- 接待台和邦布角色。
- 首版可以是 2D、预渲染视频或原创低模，不要求立即做高精 3D。
- 输入框和结果列表是普通 DOM，不烘焙到 Canvas。

交互：

- 先做确定性关键词检索。
- 输入角色、阵营、版本或内容类型。
- 返回站内真实档案链接。
- 后续再接受控 AI 问答。

#### 状态 H：正式档案

画面：

- 从沉浸场景过渡到稳定、清晰的阅读页面。
- 保留 HOOXI 品牌色、档案编号和少量录像店语言。
- 不继续使用高成本 3D 作为正文背景。

内容：

- 标题、封面、视频入口。
- 版本、章节、类型。
- 无剧透摘要与可选剧透内容。
- 角色、阵营、地点。
- 上一条、下一条和关联档案。
- 来源和更新时间。

## 2. 网站定位与核心价值

### 2.1 正式定位

**Hooxi 的《绝区零》剧情视频档案与角色关系导航站。**

HOOXI PLAY 是品牌化入口，不是独立游戏，也不是全部网站功能。

### 2.2 核心价值

| 价值 | 用户获得什么 | 实现方式 |
|---|---|---|
| 找得到 | 找到对应视频 | 版本、角色、阵营、类型、地点和关键词检索 |
| 看得懂 | 明白内容关系 | 路线图、前后节点、关联档案和剧透控制 |
| 记得住 | 记住 HOOXI 品牌 | 凌晨录像店、VHS、CRT、邦布和空间化入口 |
| 能分享 | 分享具体内容 | 稳定 URL、标题、摘要和普通 HTML 页面 |
| 可维护 | 小团队持续更新 | 结构化数据、预览、导出、差异检查和 Git 发布 |

### 2.3 目标用户

#### 核心用户 A：Hooxi 视频观众

- 从视频平台进入网站。
- 找到同系列、前后篇和相关角色内容。
- 返回视频平台观看。

#### 核心用户 B：剧情补课与回看玩家

- 按版本和章节补剧情。
- 控制剧透。
- 查角色或阵营相关内容。

#### 核心用户 C：角色与世界观用户

- 从阵营进入角色。
- 查看个人剧情、PV、主线和活动。
- 查看简洁、有来源的基础资料。

#### 内部用户

- Hooxi：产品与发布负责人。
- 编辑：维护内容和来源。
- 开发与 AI Agent：实现、验证和自动化辅助。

### 2.4 暂不服务的需求

- 完整数值模拟。
- 全图鉴。
- 开放投稿。
- 评论和社区。
- 模型下载。
- 与剧情视频无关的通用作品展示。

## 3. 功能总览

### 3.1 公开内容功能

#### 主线剧情

- 版本总览。
- 章节路线图。
- 版本筛选。
- 档案类型筛选。
- 角色、阵营、地点和关键词筛选。
- 剧透开关。
- 前后节点。
- 关联档案。
- 视频封面和播放入口。

#### 角色与阵营

建议正式栏目名称使用“角色与阵营”，不再只叫“角色故事”。

功能：

- 阵营目录。
- 阵营成员。
- 角色个人档案。
- 角色资料。
- 个人剧情。
- 相关主线。
- 相关活动。
- PV 与官方资料。
- 简要养成结构。
- 来源和待核验状态。

#### 往期活动

- 活动时间轴。
- 所属版本。
- 活动类型。
- 视频入口。
- 相关角色和阵营。

#### 幕后与对谈

- 制作记录。
- 对谈。
- 系列专题。
- 暂无内容时显示明确空状态。

#### 跨栏目搜索

- 标题。
- 角色名与别名。
- 阵营。
- 版本。
- 地点。
- 内容类型。
- 标签组合。

### 3.2 HOOXI PLAY 功能

- 轻量首屏。
- 用户主动加载 3D。
- 店外待机。
- 开门与进入。
- 店内总览。
- 左右路线。
- 左柜内容浏览。
- CSS 卡片纵深交互。
- 3D 录像带抽取与归还。
- CRT 详情展示。
- 邦布关键词导航。
- 跳过动画。
- Escape 返回。
- reduced-motion。
- WebGL fallback。

### 3.3 详情与关系导航

每条正式记录应支持：

- 稳定 ID。
- 稳定详情 URL。
- 刷新恢复当前记录。
- 视频链接。
- 来源。
- 相关角色。
- 相关阵营。
- 上一条和下一条。
- 关联记录。
- 更新时间。

建议 URL：

```text
mainline.html?id=<recordId>
events.html?id=<recordId>
behind-scenes.html?id=<recordId>
character.html?id=<characterId>
faction.html?id=<factionId>
```

### 3.4 音乐播放器

- 不自动播放。
- 用户点击后播放。
- 保存音量偏好。
- 只使用原创、授权或明确允许使用的音频。
- 不让音乐影响内容加载和页面交互。

### 3.5 编辑工作台

当前正式路线：

```text
本地登录
→ 编辑内容
→ 正式页面预览
→ 布局调整
→ 导出 data.js / layout-data.js
→ 人工检查 git diff
→ 指定文件提交
→ 推送发布
```

功能：

- 账号 Session 登录。
- 页面选择。
- 内容字段编辑。
- 图片路径编辑。
- 双击预览文字编辑。
- 点击预览定位字段。
- 桌面与移动预览。
- 布局拖动。
- 本地草稿。
- 文件导出。

未来可选：

- 编辑提交审核分支。
- 管理员查看差异。
- 管理员发布。

在前端没有完成审核、冲突和失败反馈前，不宣称在线 CMS 已完成。

### 3.6 邦布检索与 AI

#### 第一阶段：普通站内检索

- 角色名和别名。
- 阵营。
- 版本。
- 类型。
- 标题与摘要关键词。

#### 第二阶段：受控 AI

- 服务端代理调用。
- API Key 不进入前端。
- 只回答站内已发布内容。
- 回答附站内来源链接。
- 无来源时拒答。
- 限流和日志脱敏。
- 服务失败时回退普通检索。

## 5. 当前正在解决的问题

### 5.1 模块一：店内总览镜头与中央遮挡

当前真实状态：**进行中，尚未完成。**

之前有一轮验证停留在入口状态，`final=1` 查询参数实际上没有控制页面进入最终状态，因此不能作为店内总览验收。

重新使用真实滚动位置验证后，当前结果为：

- 视口：1280×900。
- 滚动位置：真实范围的 55%。
- 页面状态：`choice`。
- 滚动阶段：`reveal`。
- 场景模式：`hybrid`。
- 完整 GLB 已加载。
- 控制台错误：0。
- 画面左上至中央仍存在大型蓝黑矩形遮挡。

自动反馈回路当前连续两次稳定输出：

```text
verdict=RED
block_luma≈10.82
right_luma≈30.83
edge_rgb≈(34.00,57.48,78.65)
```

含义：

- 异常块区域明显比同高度右侧场景更暗。
- 顶边存在明显蓝色分量。
- 当前不能把模块一标记完成。

待验证原因：

1. 总览相机被人工偏移后切入近景店铺构件。
2. 某个大面积材质被错误显示为深色不透明平面。
3. 透明材质排序、双面或深度写入产生遮挡。
4. CSS/入口帧合成层仍残留。

验收标准：

- 自动检测从 RED 变为 GREEN。
- 店内总览可看清左右路线和前台。
- 不通过粗暴隐藏大量店铺结构解决。

## 8. 建模与素材计划

### 8.1 建模原则

最终场景不是照搬游戏模型，而是基于截图和视频制作可公开、可维护、性能可控的原创 HOOXI PLAY 录像店。

优先顺序：

1. 空间关系。
2. 镜头构图。
3. 关键物件识别。
4. 交互节点。
5. 材质和灯光。
6. 细节精度。

### 8.2 用户需要提供的参考资料

#### 必需截图

- 完整总览。
- 正面。
- 背面。

- 右侧。

## 18. 第一版完成定义

HOOXI 正式第一版完成，不以“页面很炫”为标准，而以以下结果为标准：

- 用户清楚知道网站是什么。
- 用户能快速找到 Hooxi 的视频。
- 用户能按版本、角色和阵营理解内容关系。
- 用户可以进入录像店，也可以直接浏览档案。
- 3D、视频、CDN或 AI 失败时，核心内容仍可用。
- 店内总览不存在大型中央遮挡。
- 正式模型和资源满足性能预算。
- 模型、第三方角色卡面、远程封面、图片、音频、字体和视频有明确来源和发布许可。
- 小团队能持续编辑、检查和发布。
- 桌面、移动、键盘和 reduced-motion 通过。
- 正式页面使用真实内容，不使用实验占位冒充完成状态。

达到以上条件后，HOOXI PLAY 才从技术样板升级为正式品牌入口。
