# HOOXI 全站视觉整合方案

消除割裂感 · 提高展示密度 · 参考绳网情报站（本地镜像取证）

日期：2026-08-05
状态：待批准（本文为方案，未动任何正式主链路文件）
参考物证：`F:\website-archives\zzz-wiki`（官方 WIKI 完整离线镜像，24G，可离线渲染真站）

---

## 0 结论

割裂感不是"效果不够炫"，是**没有唯一设计源**。全站同时存在 3 套页面家族、5 个页面基色、13 种圆角、7 种内容宽度、7 个文件重复定义 `.topbar`、6 个页面用内联 `!important` 就地改写主题。任何一处调色都会被别处覆盖，观感必然段段突变。

"内容太少"是**展示面太薄**，不是库太薄。库里有活动 246 条、主线 55 条、角色秘闻 54 条、58 位代理人完整词条；首页首屏只有 1 个可点入口，四个渲染切片上限合计 42/8/22/1 条。库很厚，露出来的很薄。

参考站值得借的**不是黄黑配色和图标宫格，是它的秩序机制**：整页只有一个底、一套卡片语言、一个强调色、一套同构标题、一个恒定间距节奏、一套模板驱动全部同类条目。这些机制与 HOOXI 的录像店基因不冲突，能直接解决割裂；而它的圆角卡矩阵皮肤撞 `design.md` §10.2 与 §10.8，必须拒绝。

真实缺口只有三处需要补内容而非补视觉：已核验视频仅 2 条、跨栏目搜索结果页缺失、`agents.html` / `gallery.html` 是数据与导航双孤岛。

## 1 诊断

### 1.1 割裂六因（均为实测）

| 序 | 根因 | 实测证据 | 观感表现 |
|---|---|---|---|
| 1 | 三套页面家族并存，各自一套 CSS 栈 | 首页 11 个 CSS；`character.html` 15+ 个 CSS 加内联 `<style>`；`agents.html` / `gallery.html` 完全内联自成一套 | 跳页时顶栏形态、基色、圆角同时突变 |
| 2 | section 级独立背景泛滥 | `theme-zzz.css` 约 230 处 background；`home-neon.css` 约 121 处；大量 `linear-gradient` / `radial-gradient` / `repeating-linear-gradient` 逐段自带底 | 每段一个渐变，段界产生硬接缝，无法消除 |
| 3 | 内联 `!important` 覆盖层 | `character.html:34-120`、`behind-scenes.html:24-52`、`stories.html:29-120`，`events` / `faction` / `cultivate` / `mainline` 同构 | 外部 CSS 与内联规则打架，全站基调无法统一调 |
| 4 | 布局量纲无 token | 页面基色 5 个（`#18171A` / `#08080c` / `#0a0a0e` / `#0a0a0f`）；圆角 13+ 种（0 到 999px 到 `50% 50% 45% 45%`）；内容宽度 7 种（900 / 1020 / 1100 / 1180 / 1280 / 1400 / 1200） | 页面间左右边界对不齐，卡片圆角从直角到胶囊并存 |
| 5 | 导航三形态 + 孤岛页 | 首页 `.topbar`；子页 `.archive-topbar`（文案"主线"vs"主线剧情"不一致）；仅 `character` / `stories` 有侧栏；`agents` / `gallery` 无任何全站导航 | 跳转后导航突然变样或消失，用户失去方位感 |
| 6 | 首屏密度过低 | Hero `min-height:100vh` 独占整屏，首屏仅 1 个 CTA；`app.js` 切片 `slice(0,42)` / `(0,8)` / `(0,22)` / `(0,1)` | 大量留白、引导极弱，观感"稀薄" |

其中 2 与 4 是**割裂的直接成因**，1 与 3 是**它无法被修复的原因**。所以施工顺序必须先 1/3/4，再 2。

### 1.2 "内容太少"的真相

库存侧（实测）：`data.js` 活动 246 条、主线 55 条、角色秘闻 54 条；`agent-enrichment.js` 58 位代理人词条 575KB；`agent-talents.js` 天赋 377KB；`cultivate-data.js` 含 guide / faqs / materials。

展示侧（实测）：首屏 1 个可点入口；四个渲染切片上限 42 / 8 / 22 / 1；Hero 独占近 100vh。

结论：**优先做铺开，不做采编**。铺开是零采编成本的密度提升。三处真缺口（视频 2 条、跨栏目搜索页、两个孤岛页）另立采编与功能任务，且按 `media-source-policy.md` 禁止用推测内容填充，空态必须诚实。

## 2 借鉴边界：借机制，拒皮肤

这是本方案最需要先取得共识的一节。参考站的视觉本质是"统一深灰圆角卡矩阵 + 黄黑强调"，而 `design.md` §10.2 禁止"把所有内容做成同尺寸圆角卡片"，§10.8 禁止"为像游戏复制官方 UI"，`zzz-archive-positioning.md` 明确【不做】"整站复制官方绳网 wiki 皮/IA"。

**直接照搬会同时踩三条既有约束，因此不采纳。**采纳的是它背后的秩序机制。

| 参考站手法（镜像一手取证） | 取舍 | 理由 | HOOXI 对应做法 |
|---|---|---|---|
| 整页唯一底色 `#1d1f1e` / `#000`，版块不自带底 | **借** | 这是它不割裂的第一成因，与基因无关 | 全站唯一 `--color-bg-stage`；section 自身背景归零 |
| 全局水印底图 `pc-page-bg.png` 贯穿整页缝合分块 | **借（换素材）** | 机制可借，素材禁抄 | 用 HOOXI 自有档案纹理/标签纸底噪，单层、低对比、贯穿全站 |
| 恒定 20px 版块间距 | **借（换值）** | 恒定节奏是关键，具体值须落 4pt 阶梯 | 模块间 48px、卡片间 16px、列表行间 8px |
| 圆角分级 4 / 8 / 12 / 16 + 胶囊 999px | **借分级，拒取值** | HOOXI 已定案 2 / 6 / 10 小圆角体系；999px 泛滥撞 §10.4 | `--radius-sm/md/lg` = 2 / 6 / 10；胶囊仅限筛选标签 |
| 唯一强调色 `#ffde00`，仅用于激活与主行动 | **借** | 与 §4"强调色不超单屏 15%"同向 | 唯一 `--color-accent`（放映黄），正文不用强调色 |
| 同构版块标题：图标 + 名称 + 右侧"全部 ›" | **借** | 跨版块视觉语言一致，是低成本高收益项 | 统一 `SectionHead`：编号 + 标题 + 结果计数 + 一个动作 |
| PC 双栏 840 + 340，侧栏 sticky 吃低权重高密度内容 | **借（换值）** | 解决"主栏为填满而拉伸" | 主 812 + 辅 320 + gap 48 = 1180，落在既有 `--content-max` |
| 首页 12 宫格图标导航 | **拒形态，借意图** | 图标宫格 + 同尺寸圆角格撞 §10.2 / §10.4；且首页宏结构锁死五段，不得新增第六段 | 在既有 `#finder` 段内做**档案抽屉式入口列**：直角 + 2px 圆角 + 等宽编号 + 线描图标，非 emoji、非同尺寸圆角格 |
| 一种内容类型一套模板，64 套模板覆盖 1920 条目 | **借（核心）** | 这是内容一致性的真正来源，也是 HOOXI 最缺的 | 同类档案共用固定分区骨架，禁止逐页手工排版 |
| 多维筛选器（稀有度/属性/特性/阵营） | **借** | 246 条活动目前无筛选，是检索力最大缺口 | 活动加 `FilterBar`：版本 / 类型 / 状态 |
| 实体互链（材料↔角色↔敌人↔攻略） | **借** | 消除孤岛页、提高留存 | 角色↔阵营↔活动↔养成材料双向挂链 |
| 黄黑配色、官方 Logo、金刚区图标、官方导航文案 | **拒** | §10.8 + §9.1.1 明令禁止；抄了 HOOXI 就失去自身识别 | 保持录像店基因：VHS 标签纸、档案编号、等宽元数据、硬边直角 |

**一句话边界**：抄它的"秩序"，不抄它的"长相"。去掉游戏资产后 HOOXI 仍须能被识别（§10.8）。

## 3 Token 收敛：建立唯一设计源

`design.md` §4 已定案 token，问题不是缺定义，是**实现没有引用它**。本期不发明新颜色名，只做"全站回归既有 token"。

### 3.1 颜色（沿用既有命名，不新增）

```css
/* 唯一页面底：全站一个值，替换现有 5 个基色 */
--color-bg-stage      /* 页面舞台底，唯一 */
--color-bg-base       /* 大区底，仅在必须与舞台分离时使用 */

/* 表面三档，承担原先由 section 渐变承担的层次 */
--color-surface-1     /* 档案卡 */
--color-surface-2     /* 卡内分区、行 hover */
--color-surface-raised/* 浮层、抽屉、弹窗 */

/* 文字三档 / 线两档 */
--color-text-1 / -2 / -3
--color-line / --color-line-strong

/* 唯一强调 */
--color-accent        /* 主动作、当前状态、关键编号；面积 ≤ 单屏 15%，正文不用 */
```

层次改由"表面抬升"表达，不再由"每段一个渐变"表达。这是消除段界接缝的关键换法。

### 3.2 量纲（三档收敛）

| 项 | 现状 | 收敛后 |
|---|---|---|
| 圆角 | 13+ 种（0 / 2 / 3 / 4 / 6 / 7 / 8 / 10 / 12 / 16 / 18 / 22 / 52 / 999 / 异形） | `--radius-sm: 2px`（标签、徽标）、`--radius-md: 6px`（卡片、图片）、`--radius-lg: 10px`（浮层、大面板）；胶囊仅限筛选标签；异形圆角全部废止 |
| 内容宽度 | 7 种（900 / 1020 / 1100 / 1180 / 1280 / 1400 / 1200） | 唯一 `--content-max: 1180px`；**唯一例外**：`stories.html` 三列工作台（§9.1.1 已授权） |
| 间距 | 多套 `max()` / `clamp()` 算式 | 4pt 阶梯：模块间 48、卡内 12–16、列表行间 8；禁止 10 / 18 / 20 / 22 / 30 等阶梯外值 |

### 3.3 需先改合同的新增项

双栏栅格需要新增布局 token，按 §12"权威关系"，**必须先更新并批准 `design.md` §4，再施工**：

```css
--col-main: 812px;
--col-aside: 320px;
/* 812 + 320 + gap 48 = 1180，与 --content-max 严格对齐 */
```

不先改合同就施工，等于用实现覆盖合同，方向错误。

## 4 统一外壳

### 4.1 SiteHeader 归一

现状 `.topbar` 在 7 个文件重复定义（`styles` / `theme-zzz` / `multi-page` / `home-neon` / `official-dna` / `game-feel` / `motion`），子页另有 `.archive-topbar`。

- 收敛为单一 `SiteHeader` 实现，高度 56px（4pt 阶梯内），结构固定为：品牌 / 一级导航 / 搜索 / PLAY 次入口，不放重复入口（§7）。
- 删除 `.archive-topbar` 与其余 6 处 `.topbar` 定义。
- **导航文案统一**：§9.2 要求导航名称全站共享，现"主线"与"主线剧情"不一致，须定一套并全站同步。

### 4.2 侧栏定位澄清

侧栏不是全站要求。§9.1.1 规定 `stories.html` 左列"保留现有公开站点侧栏"，这是该页合同。因此侧栏保持为**档案页可选左列**，不强推全站；`agents.html` / `gallery.html` 的孤岛问题用"接入 SiteHeader"解决，不靠加侧栏。

### 4.3 内联覆盖清零

6 个页面（`character` / `behind-scenes` / `stories` / `events` / `faction` / `mainline`）的内联 `<style>` + `!important` 全部移除，样式回归共享层。这是"全站基调可被统一调整"的前置条件，不做这步，后续任何调色都会被就地覆盖。

## 5 卡片语言：档案卡，不是圆角玻璃卡

参考站用"统一圆角卡"获得一致性，HOOXI 不能照搬（§10.2 禁止全站同尺寸圆角卡，§10.3 禁止渐变描边/光球/网格背景/噪点/hover 浮起，§10.4 禁止四处大圆角与胶囊）。

HOOXI 的一致性载体应为**档案卡 / 标签纸**：

- 形态：规则矩形，`--radius-sm/md`，硬边线（`--color-line`），无渐变描边、无发光、无 hover 浮起。
- 元数据：等宽 `--font-mono` 承载编号、日期、状态、版本，长度短。
- 识别手法：斜切、标签角、硬阴影**每个组件只允许用一种**（§7），正文容器保持规则矩形。
- 复用既有组件语法（§7）：`ArchiveCard`（封面/回退、类型、标题、无剧透摘要、版本、明确动作）、`RecordRow`（高密度结果，与卡共用状态与元数据语法）、`SectionHead`、`FilterBar`、`SourceBlock`、`EmptyState`。
- 首层文字预算按 §7.1：标题 + 至多一个分类/版本 + 两行摘要 + 一个主来源动作；其余进原生 `<details data-archive-disclosure>`。

一致性来自"同一套卡骨架 + 同一套状态语法"，不来自"所有块都是同一个圆角矩形"。

## 6 密度铺开（严格在首页五段合同内）

§9.1.0 锁死首页宏结构为五段：`Cinematic Marquee → Direct Finder → Featured Agents → Archive Reels → Source / Footer`。以下改动**全部在段内**，不新增第六段，不改 Hero 四张登记片源，不改控件集（仅页码 + 暂停）。

| 段 | 现状 | 改动 | 合规依据 |
|---|---|---|---|
| 1 Cinematic Marquee | `min-height:100vh`，首屏仅 1 个 CTA | 降至约 68vh，使第二段顶部在首屏露出；Hero 首层仍只保留一个导语 + 一个主动作 + 一个安静次入口 | §9.1.0 未规定 Hero 高度；§7.1 文字预算不变 |
| 2 Direct Finder `#finder` | 入口段，密度低 | 做成**档案抽屉式入口列**：栏目直达 + 各栏目实时条目计数 + 搜索。直角 + 2px 圆角 + 等宽编号 + 线描图标 | 锚点 `#finder` 不变，段序不变；形态避开 §10.2 / §10.4 |
| 3 Featured Agents | `slice(0,8)` | 提升至 12–16（库有 58 位），改 `RecordRow` 密度形态承载尾部 | 段内密度未被合同限制 |
| 4 Archive Reels | `slice(0,22)`，246 条活动无筛选 | 主辅双列（主 812 / 辅 320）：主列分类铺开条目，辅列吃"最近更新 / 版本状态 / 核验状态"等低视觉权重高密度信息 | 双列是段内布局，非新增段 |
| 5 Source / Footer | 已有 | 保留来源与非官方边界声明，不动 | §9.2 |

其余档案页同步提高密度：条目卡首层收紧到 §7.1 预算，尾部信息进 `<details>`，用"更多行数"而不是"更大留白"填充版面。

## 7 检索与互链

这三项是参考站真正的检索力来源，也是 HOOXI 的实际缺口。

1. **活动筛选**：246 条活动目前无筛选，加 `FilterBar`（维度：版本 / 类型 / 状态），要求可清空、显示结果计数、移动端可折叠（§7）。
2. **跨栏目搜索结果页**：`HOOXI-FORMAL-SITE-GAP-CHECKLIST.md` 已列为未关闭缺口，现仅复用角色目录筛选。补统一结果页，覆盖角色 / 活动 / 主线 / 幕后 / 养成。
3. **实体互链**：角色 ↔ 阵营 ↔ 活动 ↔ 养成材料双向挂链，消除"孤立图文页"。数据基础已在 `data.js` → `agent-enrichment.js` → `agent-catalog.js` 链上。
4. **孤岛页归位**：`agents.html`（`assets/data/agents.json`）与 `gallery.html`（`wallpapers.json`）数据源独立于主链，需先定性——并入主数据链，或明确降级为原型并从公开面移除。**这一步需要你拍板**，两条路成本差别很大。

## 8 分期与验证

每期完工后才刷指纹基线，且刷基线须单独取得授权。

| 期 | 内容 | 验证项 | 预期视觉变化 |
|---|---|---|---|
| **P0** | Token 地基：5 基色归一、13 圆角收 3 档、7 宽度收 1 档 + stories 例外；不动布局不动观感 | `npm run test:content` / `test:formal` / `test:ui` 三绿；`test:contrast` ≥ 4.62:1；UI 截图矩阵差异应接近零 | 几乎不可见（这是最安全的第一刀） |
| **P1** | 内联 `!important` 清零（6 页）；section 背景归零，层次改走表面三档 | `test:contrast`、`test:ui`（`blockingFailures:0`） | 段界硬接缝消失，全站基调开始可控 |
| **P2** | `SiteHeader` 归一（删 6 处重复 + `.archive-topbar`）；导航文案统一；`agents` / `gallery` 接入外壳 | `test:ui` 深链与交互、键盘可达、移动断点 | 跳页不再突变，孤岛消除 |
| **P3** | 首页五段内密度铺开（Hero 降高、`#finder` 入口列、切片上调、Reels 主辅双列） | `test:ui`、首屏 LCP ≤ 2.5s / CLS ≤ 0.1 / INP ≤ 200ms；Hero 暂停原因集合回归 | 首屏由 1 入口提升到高密度入口面 |
| **P4** | 检索层：活动 `FilterBar` + 跨栏目搜索结果页 + 实体互链 | 筛选状态可感知、结果计数正确、空态诚实、深链可恢复 | 246 条活动首次可被检索 |
| **P5** | 原型 CSS 从正式链路移出 | `test:formal`、`test:ui` | 无 |

**P0 是唯一"改代码但不改观感"的一期，建议单独走完并封板，再进 P1。**它能把后续所有调整变成一处生效。

## 9 门禁与风险

- **必撞三道门禁**：动全站视觉必然触发 `check-formal-site-gate.py`（`GATE_FAIL`）+ `test:contrast` + `test:ui`。指纹覆盖 `index.html` / `app.js` / `styles.css` / `multi-page.css` / `motion.css` / `theme-zzz.css`（含其 `@import` 的 `wiki-readability.css`）/ `data.js` / `agent-catalog.js` / `agent-enrichment.js` / `stories.*` / `character.*` / `faction.*` / `editor.*` / `site-motion.js`。每期须先授权，完工经你同意后才 `--write` 刷基线。
- **对比度硬线**：深色底浅字 ≥ 历史基线约 4.62:1；正文 WCAG AA 4.5:1、大字 3:1、焦点与边界 3:1。
- **`tape-wall-sample.html` 是正式 `PUBLIC_PLAY` 路由**，P5 清理原型 CSS 时**不得删** `tape-wall-sample.css`。这是最容易误伤的一处。
- **`wiki-readability.css` 76KB 不是孤儿**：它经 `theme-zzz.css` 的 `@import` 进入正式链路。动它前必须先确认 `@import` 链，审计中"疑似孤儿"的判断在此更正。
- **`theme-zzz.css` 204KB 不做大重构**：本方案只要求"减背景声明、回归 token"，不拆分文件。拆分风险远高于收益。
- **`stories.html` 三列同屏是硬合同**（§9.1.1）：收敛内容宽度时必须保留其 1180px 例外，且不得以横向溢出或重叠换取同屏。
- **新增布局 token 须先改合同**（§12）：`--col-main` / `--col-aside` 落地前先更新并批准 `design.md` §4。
- **`progress.md` 现存唯一记录已失效**：2026-06-15 那条"注入 `official-wiki.css` 米哈游维基风格黄黑全屏区块"与后续所有定案矛盾，本方案不参照它，也不假设 `index.html` 保留 `official-wiki` 区块。首页第 5 段 `.official-wiki#officialWiki` 目前仍在，与五段合同冲突，需在 P3 一并处理。
