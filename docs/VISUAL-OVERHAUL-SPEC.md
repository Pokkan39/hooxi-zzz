### 3.1.1 许可证边界（重要，不得越线）

- **Swiper 是 MIT**，无限制。
- **GSAP 是 Standard "no charge" license**，适用于对最终用户免费开放的站点。本站是粉丝非官方免费档案站，符合适用范围。
- **禁止使用需要 Club GSAP 付费会员的插件**：`SplitText`、`ScrollSmoother`、`MorphSVGPlugin`、`DrawSVGPlugin`、`Flip`、`InertiaPlugin`、`CustomEase` 等。只允许用 `gsap` 核心与 `ScrollTrigger`。
- 因此第 4.2 节的「文字逐字浮现」**不得用 SplitText**，改为自行拆 `span` 后用 `gsap.from(..., {stagger})`。做法见 4.2 节。
- 若将来需要付费插件，必须先告知用户并取得授权，不得自行引入。

### 3.2 与现有 `motion.css` 的关系

`motion.css` 有 654 行现存动效。**不要删除它**。新动效通过 GSAP 施加在 JS 层，CSS 只保留静态终态与 `prefers-reduced-motion` 回退。

如发现新旧动效在同一元素上冲突，优先保留 GSAP 版本，并在 `motion.css` 中用注释标明该规则已被 JS 接管，不要直接删行。

### 3.3 性能红线

获奖站的评分里「好用」占 30%，性能是硬指标。必须满足：

| 指标 | 目标 |
| --- | --- |

### 4.6 第 05 条详解：信号锁定入场

用户否决了原来的「淡入上移」，理由是太弱。现行做法是**文字由雪花凝聚成形**。

**关键区别（第一版做错过，务必看清）：** 雪花不是盖在文字上面的遮罩层，而是**文字本身的材质**。用 `background-clip:text` 把噪点裁进笔画范围内，颗粒只出现在字形里，然后慢慢聚拢成清晰的字。

DOM 结构（由 JS 自动包装，不要手改 HTML）：

```html
<div class="stagger__item"><span class="tvtext" data-text="01 · 代理人档案">01 · 代理人档案</span></div>
```

三层协同：

1. 真实文字 `color:transparent` → 锁定后变 `var(--text)`
2. `::before` 用 `content:attr(data-text)` + `background-clip:text` 承载噪点，从 `blur(3px) scaleX(1.06)` 收敛到清晰
3. `::after` 一道亮带掠过笔画

时序统一用 `--lock-delay` 变量，四个条目依次 `0s / .22s / .44s / .66s`。**间隔必须 ≥ .22s**，原来的 .12s 看不清节奏。

**噪点必须逐帧抖动。** 靠 JS 每帧随机写 `--sx / --sy`：静止的颗粒图看着像屏幕脏了，只有抖起来才像信号没锁住。实测连续 10 帧应得到 10 个不同位置值。抖动结束后清掉变量，不留残留。

### 4.7 第 17 条详解：琴键式邻近缩放

用户要求「随着鼠标的位置每个条目的大小也不一样，就像划过钢琴一样」。

```js
scale = 1 + 0.42 * Math.max(0, 1 - (distance / radius) ** 2)
```

`radius` 取整排宽度的 1/5，使同时受影响约 3–5 格。实测波峰 1.42、邻居依次 1.35 / 1.13 / 1.00，左右单调递减。

**只写 `transform` 与 `filter`，绝不动宽高。** 用宽高做缩放会把邻居推开，整排跟着抖，那就不是琴键而是塌方。

必须 `pointermove` 记录坐标 + rAF 统一写样式，`pointerleave` 平滑复位。12 格须是真实 `button`，键盘 focus 时给等效反馈。

### 4.8 第 20 条详解：电视信号缓冲转场

用户定的方向。相比胶片过带的好处是：**「信号在缓冲」本身就是等待的合理解释**——网速慢就多雪花一会儿，胶片过带是固定时长动作，没法自然延长。

五层纯 CSS，无图片。GSAP timeline 编排，总时长 **760ms**（实测 904ms 含收尾）：

| 时刻 | 表现 |
| --- | --- |
| 0–60ms | 顶部电视彩条闪断（灰黄青绿紫红蓝），雪花瞬间盖满 |
| 60–150ms | 彩条收掉，雪花持续抖动 |
| 160–320ms | 横向撕裂错位两次 |
| 120–540ms | 亮带从上往下滚过（场同步没锁住的典型现象，最有辨识度的一笔） |
| 380ms | **雪花最浓时换页**，用户看不到切换动作 |
| 500–720ms | 雪花退去，扫描线最后收掉，信号重新锁定 |

正式接入：点击站内链接先拦住跳转播「信号中断」，新页面加载完成播「重新锁定」，中间雪花段盖住真实加载空档。

### 4.9 第 21 条详解：常驻磁带机播放器

原型是**索尼 TPS-L2**（1979 年第一代 Walkman）。特征据史密森尼博物馆、MoMA、Design Museum 藏品记录还原，不是凭印象画。

**必须还原的特征：**

| 特征 | 做法 |
| --- | --- |
| 正面半透明窗 | 能看见里面磁带在转，**这是最重要的辨识点** |
| 双耳机孔 | 顶部两个圆孔，标 `GUYS` / `DOLLS`（原机为两人同听设计） |
| 右侧铝合金饰条 | 竖向金属条，多段渐变做高光 + 拉丝纹 |
| 橙色 HOT LINE 钮 | 按住把音量压到 20%，松开恢复（还原原机功能） |

**商标合规（必须遵守）：** 本站是粉丝非官方站，**不得出现 `SONY`、`WALKMAN` 字样**。原 SONY 位改为 `HOOXI`，型号条位改为 `ZZZ ARCHIVE`，保持同样排版位置与字重。这是致敬工业设计，不是仿冒。

**机身颜色随角色代表色变化**（用户核心要求）：

- 数据源 `agent-xray.js` 的 `l` 字段，**不用 `c`**（理由见 6.1）。
- 取到 `[r,g,b]` 后转 HSL，**明度锁进 40%–58%**（塑料质感区间），保留色相与饱和度，这样深色浅色角色都能看清。
- 缺 `l` 的角色（1 个）降级到 TPS-L2 原型蓝，不得崩溃。
- **铝条保持银灰、HOT LINE 保持橙色，都不跟随角色色。** 金属就是金属；橙钮是标志，跟着变色就认不出是 Walkman 了。
- 切换用 GSAP 平滑过渡，不要瞬间跳变。

**去文字化（用户明确批评「太多文字反而导致没有质感」）：** 原播放器有 5 处中文标签（`音乐播放器（可选）`、`NOW ON TAPE`、`未选择音乐`、`顺序`、`歌单`），新方案视觉上中文标签为 **0 处**，语义全部落在 `aria-label`。按钮用 CSS 画的几何图形，不用 emoji 不用文字。

**曲名必须清洗：** `三Z-STUDIO _ HOYO-MiX - chaos_exe.ogg` → `chaos_exe`。去后缀、弱化厂牌前缀，只留实际曲名。过长时跑马灯滚动，容器给完整曲名 `aria-label`、滚动内容 `aria-hidden`，避免反复朗读。

**尺寸：** 展开态 `--tps-zoom:.62`（约 184×191），296px 原尺寸太占视野。用 `zoom` 不用 `transform:scale`——后者只改视觉、原尺寸仍占布局，常驻时会留空白挡内容。收起态 78×35，`zoom` 收回 1 且 `width:fit-content`（用 `auto` 会撑满整行，实测 1280px）。

**关闭与唤回：** 必须能关，且关闭后页面角落留极小唤回入口，状态存 `localStorage`。只能关不能开是不合理的。

**全站常驻的真实限制（必须如实告知用户，不得美化）：**

- 现状：正式站播放器**只存在于 `index.html`**，其余 7 个页面完全没有。
- 推荐做法：抽成 `zzz-player.js`，每页引一行、DOM 由 JS 注入，避免维护 8 份重复 HTML；播放进度与曲目索引存 `sessionStorage`，跳转后恢复。
- **硬限制：传统多页站每次跳转都整页重载，音频一定会中断重播，做不到真正连续播放。** 记住进度只让体验接近连续，严格说是「断掉之后重连」，中间有停顿。
- 想真正无缝必须走 SPA 或 View Transition 局部换内容，让播放器 DOM 从不销毁——那是重构整站路由的量级，**建议单独立项，不要混在视觉改造里做**。

## 5. 招牌效果：鼠标视差（裸眼 3D）

获奖站的共同特征是**一个招牌瞬间，不是二十个特效**。全站到处在动会显得廉价。

### 5.1 已废弃方案（不要再做）

原先推荐的「滚动钉住讲故事」（`position:sticky` + `pin`）**已被用户明确否决**，理由是把用户强制固定在某一屏、想往下看却走不了，等于抢走用户的操作权。**这条与最高指令第 6 条冲突，任何形式的锁滚动都不允许。**

### 5.2 现行方案：鼠标驱动的多层视差

样本见 `prototype/art-samples/index.html` 的 `s08` 区块，已实测通过。

**四层景深，各层位移倍率不同：**

| 层 | 内容 | 倍率 |
| --- | --- | --- |
| 最远 | 背景影画 `assets/mindscape/default/*.webp`（2880×1080） | 0.25 |
| 中 | 氛围光效（纯渐变，不用图） | 0.5 |
| 主体 | 透明角色立绘 `assets/portraits/*-portrait.webp`（1600×1800） | 1.0 |
| 最前 | 文字与 UI 标签 | −0.3（反向） |

**关键素材事实：** `assets/portraits/*-portrait.webp` 本身就是**透明背景立绘**，天然是独立角色层，**不需要抠图**。配 `mindscape/default/` 的宽幅影画当背景，直接就是「背景 + 角色」两层结构。

**位移幅度必须按轴分开给**（实测数据，直接照用）：

```js
var PX_RANGE_X = 96;   // 横向最大位移
var PX_RANGE_Y = 26;   // 纵向最大位移
```

原因：实测立绘左右各有约 321px 余量，但底部只剩 1px。横向可以放开做视差才明显，纵向必须收着，否则一动就切脚。

**缓动必须用 GSAP**（最高指令第 1 条）：

```js
L.toX = gsap.quickTo(L.el, 'x', { duration: 0.6, ease: 'power2.out', overwrite: 'auto' });
L.toY = gsap.quickTo(L.el, 'y', { duration: 0.6, ease: 'power2.out', overwrite: 'auto' });
```

不要自己写 lerp 循环。`quickTo` 内部走 `gsap.ticker`，性能与调度都由库负责。

**实测验收标准**（鼠标从最左移到最右，各层位移量）：

| 层 | 实测行程 |
| --- | --- |
| 背景 | 42px |
| 光效 | 84px |
| 立绘 | 168px |
| 文字 | 50px（反向） |

立绘行程应为背景的约 4 倍，且文字方向相反。达不到这个差距就说明景深没做出来。

### 5.3 三个必避的坑（样本页实测踩到）

1. **立绘层不能向外扩。** 曾用 `inset:-6%` 配合容器 `overflow:hidden`，结果人物膝盖被容器边缘直接切断，看起来像被斜切裁开。必须 `inset:0` 并给底部留位移余量（样本用 `--hero-slack:44px`）。
2. **立绘不要做 3D 倾斜。** `rotateX/rotateY` 配合 `overflow:hidden` 同样会切边。已移除。
3. **背景不能压太暗。** 曾用 `brightness(.62)`，角色脸看不清。改为 `brightness(.86)`，并只在左侧做渐变压暗给文字让位，右侧保持通透。

### 5.4 成本

中。比锁滚动方案低，因为不需要精细调滚动区间，且不接管滚动就不会与页面滚动打架。

### 6.2 镜像里存在但无法自动定位的素材

**这一节是本次调查最重要的结论，不要误读为「素材不存在」。**

本地 wiki 镜像 `F:\website-archives\zzz-wiki` 规模为 **1920 个词条页、12536 个资源、约 23GB**，其中 **11414 张 PNG**。属性图标与职业图标**极可能就在其中**。

但**无法建立「图标 → 它代表什么」的可靠映射**，原因有二：

1. 文件名全是哈希（如 `b318c4dfe95114081a7991a89f63c829_2755558221303035935.png`），路径不含语义。
2. 词条列表接口的 `filter_values` 字段为空，属性与职业的值不在 JSON 里，而在页面渲染层。

已尝试两种反查，均失败：宽匹配得出的结果自相矛盾（同一个 URL 同时匹配到「火」「击破」「异常」，明显是把整块 JSON 的标签和图片混在一起，该结果已被否决）；严格一对一配对结果为零。扫描脚本留在 `artifacts/scan-wiki-icons.py`，结果在镜像根的 `icon-scan.json`。

**结论：靠自动化从 11414 张哈希命名的图里挑出正确图标不现实。** 需要人工确认或换数据源。

- **属性/职业图标**：沿用现有 `zzz-ui.js` 的手绘 SVG（`ICONS` 表）或文字标签，外形按 HUD 风格加边框。**严禁凭印象仿制官方图标形状**——本站 57 人的属性、职业字段都是准确数据，配一套走形的仿制图标会让准确数据看起来不可信。

## 9. 可访问性硬要求

不可省略，它们同时是获奖评分里「好用」那 30% 的组成部分。

1. **`prefers-reduced-motion: reduce`** 下：所有空间位移动效降为 ≤150ms 透明度渐变；自定义光标回退系统光标；视差各层归位；逐字浮现与信号锁定直接显示清晰终态；转场退化为直接切换；磁带机轮盘与律动静止但**播放功能必须仍可用**。

   **实现要点（样本页踩过坑）：** reduce 规则要挂在 `html:not(.force-motion)` 下，并提供「强制预览」开关，否则开了系统减动效的用户永远看不到效果、会以为页面坏了。**JS 侧的判定必须直接读 `document.documentElement.classList.contains('force-motion')`，不要只信内部变量** —— 样本页曾出现 class 已加上、CSS 已放行，但 JS 那层还在拦着，导致视差、磁吸、琴键全部不恢复。
2. **`:focus-visible`** 必须可见，对比度 ≥ 3:1，且**不得对焦点环做动画**。
3. **键盘可达**：Swiper 轮播必须支持方向键；自定义光标不得吞掉焦点。
4. **对比度**：正文 ≥ 4.5:1，大字 ≥ 3:1。荧光绿 `#d8fa00` 在深底上对比度很高，但**不得用作正文色**（过于刺眼）。
5. **点击目标** ≥ 44×44px。
6. **逐字浮现的 `aria-label`**：拆 span 后必须给容器加原文 `aria-label`，否则屏幕阅读器逐字朗读。
